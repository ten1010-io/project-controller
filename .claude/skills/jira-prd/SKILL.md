# jira-prd

한 줄 아이디어를 **대화로 구체화 → PRD 확정 → Jira 이슈 생성** 으로 마무리한다.
`/jira-new` 가 "이미 정해진 걸 바로 티켓화" 라면, 이 스킬은 "무엇을 만들지부터 같이 정리" 하는 앞단이다.

Jira 필드 매핑·고정값(cloudId/projectKey/team/커스텀필드 ID·물어봄 항목)은 **`.claude/commands/jira-new.md` 가 SoT** — 여기서 재정의하지 않고 그대로 따른다.

## 1. Discovery (핵심)

목표: 추측으로 설명을 지어내지 않도록, PRD 각 섹션에 **실제 근거**가 채워질 때까지 사용자와 논의한다.

- **한 번에 2~4개**씩, 답이 모호하면 파고든다(grill 스타일이되 건설적으로). 라운드는 최대 3회 — 그 안에 안 정해진 건 PRD "열린 질문" 으로 남긴다.
- 답이 이미 나온 섹션은 다시 묻지 않는다. 사용자가 "이 정도면 됨" 하면 즉시 다음 단계로.
- 아래를 커버할 때까지 진행:

  | 물어볼 것        | 노리는 PRD 섹션           |
  | ---------------- | ------------------------- |
  | 왜 필요한가/문제 | 배경                      |
  | 누가/어떤 상황   | 대상 사용자·시나리오      |
  | 뭘 하게 되나     | 요구사항(기능)            |
  | 뭘 안 하나       | 비범위                    |
  | 언제 "완료"인가  | 완료 조건                 |
  | 영향 모듈/proto·외부시스템 | 의존성 (proto·gRPC·K8s/Harbor/ES 등) |

- 코드베이스 맥락이 필요하면 `Explore`/grep 또는 `codebase-analyst` 로 관련 모듈·도메인·proto 를 훑어 근거를 보강한다(선택).

## 2. PRD 작성

아래 구조로 정리해 사용자에게 보여주고 확정받는다. (원하면 `scratchpad/` 에 `.md` 로도 저장)

```
# <제목>

## 배경
왜 필요한가 (문제/기회)

## 목표 · 비목표
- 목표: ...
- 비목표: ...

## 대상 사용자 · 시나리오
...

## 요구사항
- [기능] ...
- [비기능] ... (선택)

## 완료 조건
- [ ] ...

## 의존성 · 참고
- API: <문서 링크>
- ...

## 열린 질문
- ...
```

## 3. Jira 생성

- PRD 확정 후 **`/jira-new` 절차(§고정값·필드 매핑·물어봄)** 를 그대로 실행.
- **description = PRD 본문** (열린 질문 포함). 제목은 PRD `#` 제목 → `[JA] ...` 컨벤션으로 (jira-new SoT).
- 물어봄 항목(스프린트·SP·수정버전·우선순위·담당자)은 discovery 중 이미 나온 값이 있으면 그걸 default 로 제시.
- 생성 후 이슈 키·URL 보고. 바로 착수하려면 `/jira-fix AIP-xxxx` 안내.

## 규칙

- discovery 없이 곧장 티켓 만들지 않는다 — 최소 1라운드는 대화. (그게 이 스킬의 존재 이유)
- 그래도 정보가 안 나오면 "열린 질문" 에 남기고 생성 — 완벽 대기로 멈추지 않는다.
- 생성은 비가역 — PRD·필드 초안 확인 후 호출.
