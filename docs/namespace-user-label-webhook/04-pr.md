# PR 문구

## Title
feat: inject and guard user labels on cluster-scoped Namespace via userrelationship webhook (AIP-2739)

## Summary
- aipub admin이 아닌 aipub member가 Namespace UPDATE로 소유자 라벨(username/userid)을 추가/변경/삭제하려 하면 403으로 거부한다 (`UserLabelGuardReviewHandler` 신규). admin과 aipub 그룹 밖 주체는 제한하지 않는다.
- userrelationship 뮤테이팅 웹훅을 cluster-scoped `Namespace` CREATE까지 확장하여, 네임스페이스 생성 시 요청자 토큰 기반 `aipub.ten1010.io/username`/`aipub.ten1010.io/userid` 라벨을 주입한다.
- Namespace 오브젝트 자체는 allowlist(`project.ten1010.io/allowlisted: "true"`)여도 라벨을 주입한다 (allowlist 스킵은 "allowlist 네임스페이스 안의 리소스" 규칙).
- `UserOwnerReviewHandler`의 AipubUser ownerReference 삽입은 Namespace에서 명시적으로 제외한다 (AipubUser 삭제 시 네임스페이스가 GC로 함께 삭제되는 위험 차단).

## Changes
- `java-webhook-configuration.yaml`: userrelationship 웹훅 rules에 `""/v1/namespaces CREATE, UPDATE (scope: Cluster)` 추가. Namespace에는 namespaceSelector가 오브젝트 자신의 라벨에 평가되어 기존 시스템 네임스페이스 제외 목록이 그대로 적용됨.
- `V1AdmissionReviewRequest`: `oldObject` 필드 추가 (UPDATE 라벨 변경 감지).
- `UserLabelGuardReviewHandler` 신규 + `MutatingConfiguration` 배선: Namespace UPDATE에서 소유자 라벨 변경 감지 시 admin 아닌 member를 403 거부.
- `V1AdmissionReviewUtils`: `isNamespaceRequest()` 헬퍼 추가 — Namespace CREATE는 `request.namespace`가 자신의 이름으로 채워지므로 kind 기반으로 판별.
- `UserLabelReviewHandler`: Namespace CREATE 처리 (allowlist 스킵 우회, 비멤버는 무변경 allow). 기존 namespaced 경로 불변.
- `UserOwnerReviewHandler`: Namespace canHandle 제외.
- 단위 테스트 6건 추가.
