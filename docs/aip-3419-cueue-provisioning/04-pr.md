## Title

```
feat: Cueue 프로젝트 권한·프로비저닝 라벨 추가 (AIP-3419)
```

## Summary

AIPub 5.2 코스터 신버전에서 `SchedulingQueue` 가 삭제되고 **`Cueue`**(`cueues.coaster.ten1010.io`,
Cluster scope)가 그 자리를 대신한다. Cueue 는 프로젝트마다 하나씩 프로젝트와 같은 이름으로 Coaster 가
자동 생성하는데, 그 전제 조건(네임스페이스 라벨·어노테이션, 노드 라벨)을 project-controller 가 만들어
줘야 한다. 프로젝트 역할별 Cueue 접근 권한도 함께 부여한다.

설계 판단 세 가지를 PR 본문에 남긴다.

**1. `list` 를 부여하지 않았다.** Confluence 문서 §9 는 매니저·멤버에게 `get`/`list` 를 적어뒀지만
`list` 는 넣지 않았다. `list` 는 컬렉션 요청이라 `resourceNames` 로 좁혀지지 않는다 — 규칙에 넣어도
매칭되지 않아 거부되고, 동작시키려면 `resourceNames` 를 떼야 하는데 Cueue 가 Cluster scope 라 **전체
Cueue(= 전체 프로젝트 목록)가 모든 멤버에게 노출**된다. 프론트는 k8s LIST 대신 `UserAuthorityReview`
권한 분석으로 접근 가능한 리소스를 집계해 쓰므로 필요하지도 않다. 기존 `gpuConfigs`·`nodeResources`
규칙이 `get` 만 주는 것과 같은 이유다.

**2. 노드 라벨에 `isProjectManaged` 게이트를 뒀다.** `getAllBoundProjects(V1Node)` 가 `project-managed`
라벨을 보지 않아 비관리 노드도 바인딩으로 잡힌다. `reconcileNodeAnnotations` 가 바로 그 이유로
bound-projects 어노테이션을 게이트하고 있고, 새 라벨은 같은 성격의 프로젝트 파생 상태라 동작을 맞췄다.
접두 제거를 게이트 **앞**에 둬서 노드가 프로젝트 관리에서 빠질 때 기존 라벨이 회수된다.

**3. Cueue DTO 를 만들지 않았다.** 이 컨트롤러는 Cueue 객체를 읽지도 쓰지도 않는다 — 전제 조건을
깔고 권한을 주기만 한다. RBAC 룰은 apiGroup·resource 를 문자열로 받고(`CUEUE_RESOURCE_PLURAL` 하나면
끝), 라벨·어노테이션 리컨실이 만지는 객체는 `V1Node`·`V1Namespace` 뿐이다. 초판에 `V1alpha1Cueue` 외
nested 5종을 만들었다가 **참조처 0건의 dead code 라 걷어냈다**. 인포머·`K8sApiProvider` 에도 등록하지
않았으므로 역직렬화될 경로 자체가 없다. 필요해지는 시점은 Cueue validating webhook 을 넣기로 결정할
때이며, CRD 스키마가 `kubernetes/examples/crd.yaml` 에 남아 복원 비용은 낮다.

`cueue.coaster.ten1010.io/auto-enqueue` 라벨은 **범위 밖**이다. 프로젝트별 on/off 운영 설정이라 Project
에서 파생할 수 있는 값이 아니고, AIPub 어드민이 직접 설정한다(`aipub-admin` 이 `cluster-admin` 바인딩이라
별도 권한 작업 불필요). 컨트롤러가 매 주기 `"true"` 를 심으면 끈 설정이 되살아나므로 읽지도 쓰지도
않으며, 외부가 붙인 값이 보존되는지만 테스트로 고정했다.

## Changes

**RBAC** (`ReconciliationService`)
- `ProjectApiConstants` 에 `CUEUE_RESOURCE_PLURAL`
- `cueuesApiRule` 을 `gpuConfigsApiRule` 뒤에 추가. 매니저 `get`/`patch`/`update`, 멤버 `get`,
  `resourceNames` = 프로젝트 이름

**프로비저닝 전제 조건**
- 노드: `project-name.aipub.ten1010.io/<proj>: ""` — `reconcileNodeLabels` 가 `boundProjects` 를 받도록
  시그니처 변경
- 네임스페이스: label `cueue.coaster.ten1010.io/provisioning-enabled: "true"` + annotation
  `cueue.coaster.ten1010.io/node-selector`. **`reconcileNamespaceAnnotations` 신설** 후
  `NamespaceReconciler` 의 생성·갱신 양쪽 경로에 배선
- `OnUpdateFilterFactory.projectNamespaceFilter()` 에 **annotation 비교 추가** — informer resync period
  가 `0` 이라 이게 빠지면 누가 어노테이션을 지워도 Project ADD/DELETE 나 재기동 전까지 복구되지 않는다

**기타**
- `kubernetes/examples/crd.yaml` 에 Cueue CRD append
- 테스트 24건 신규 (Cueue 룰 4 / 프로비저닝 14 / watch 필터 6)

## 하위 호환성 · 배포 영향

- **배포 직후 기존 프로젝트 ClusterRole 이 1회 UPDATE 된다.** `ClusterRoleReconciler` 가 룰 리스트를
  `List.equals`(순서 비교)로 판정하는데 규칙을 중간에 삽입했기 때문이다. 의도된 1회성이며 이후 멱등이다.
- 노드 watch 필터를 10곳 이상 컨트롤러가 공유해 배포 직후 1회 리컨실 버스트가 있다(전부 no-op).
- `aipub-web` 변경 불필요 — 프론트는 `UserAuthorityReview` + 이름별 GET 폴백 구조다.
- Helm 차트 RBAC 변경 불필요 — 컨트롤러 SA 가 이미 `*/*/*`.

## 주의 — 새로 생긴 제약

`project-name.aipub.ten1010.io/` 접두로 시작하는 키를 **NodeGroup 의 `spec.nodeSelector` 에 쓰면 안
된다.** `getBoundNodeGroupsByNodeSelector` 가 부분집합 판정이라, 프로젝트 A 의 키를 selector 로 가진
NodeGroup 을 프로젝트 B 에 바인딩하면 A 의 노드가 B 에도 전이 바인딩돼 테넌트 경계가 넓어진다. 현재
이 키를 쓰는 NodeGroup 은 없고(워크스페이스 전체 grep 0건), 상수 Javadoc 에 금지를 명시했다.
