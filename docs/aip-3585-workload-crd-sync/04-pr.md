## 🔍 여기만은 꼭 봐주세요!!

diff 의 97% 는 `kubernetes/examples/crd.yaml` 기계 재생성분이라 읽을 필요가 없다. 판단이 필요한 건 셋이다.

- **`workspaces` 예시가 `v1` → `v1beta1` 로 통째로 바뀐다.** 클러스터에 `v1` 은 없다(현행은 v1beta1 단일, served+storage). 구 예시를 적용해 온 로컬 환경이 있다면 CRD 가 교체된다 — 이 전제가 맞는지만 봐주세요.
  [kubernetes/examples/crd.yaml#L639](https://github.com/ten1010-io/project-controller/blob/bbc1f4b12dacbc64a88a6954395cc723b1266ace/kubernetes/examples/crd.yaml#L639)
- **ServiceExposure DTO 를 만들지 않은 판단.** 이 CRD 에도 `rules[].inference` 가 추가됐지만 인포머·RBAC·웹훅 참조가 0건이라 dead code 가 된다(AIP-3419 의 Cueue 와 같은 결론). 나중에 webhook 을 넣기로 하면 그때 만든다.
  [docs/aip-3585-workload-crd-sync/01-plan.md](https://github.com/ten1010-io/project-controller/blob/bbc1f4b12dacbc64a88a6954395cc723b1266ace/docs/aip-3585-workload-crd-sync/01-plan.md)
- **`tools[].type` 을 enum 이 아닌 `String` 으로 둔 판단.** CRD 에 `vscode` 가 추가됐는데, enum 으로 바꾸면 다음 tool 이 들어올 때 역직렬화가 깨진다. 컨트롤러가 이 값으로 분기하지도 않는다.
  [V1beta1WorkspaceTool.java](https://github.com/ten1010-io/project-controller/blob/bbc1f4b12dacbc64a88a6954395cc723b1266ace/src/main/java/io/ten1010/aipub/projectcontroller/domain/k8s/dto/V1beta1WorkspaceTool.java)

## Summary

- cluster10(`c10-m1`) 배포본과 `develop` 을 대조해 **Workspace(v1beta1) 모델에 빠져 있던 3건**을 채운다.
- Operation 은 어제 `623862f`(AIP-2269)에서 `expose.inference` 가 들어가 이미 클러스터와 맞다. 같은 expose 구조를 공유하는 Workspace 만 빠져 있었다.
- 어긋나 있던 `kubernetes/examples/crd.yaml` 의 `operations`·`workspaces` 참조 사본을 클러스터 기준으로 다시 맞춘다.
- 리컨실 경로가 워크로드 CR 에서 이름·라벨만 쓰기 때문에 DTO 필드명을 틀려도 런타임 증상이 없다 — 인포머와 같은 Gson 으로 역직렬화를 고정하는 테스트를 함께 넣는다.
- 관련 티켓: [AIP-3585](https://ten1010.atlassian.net/browse/AIP-3585) (상위 에픽 AIP-2646)

## Changes

- **DTO (Workspace v1beta1)**: `V1beta1WorkspacePortExpose` 에 nested `Inference{host, path}` 추가. `tls` 가 없는 것은 의도 — 추론 노출은 항상 HTTPS 라 CRD 에도 없다.
- **DTO (Workspace v1beta1)**: `V1beta1WorkspaceSuspendOption`(`commit{enabled, repository, applyImage}`) · `V1beta1WorkspaceSuspendCommitStatus`(`image, prevImage, appliedImage`) 신규 + Spec/Status 배선. 최상위 필드 1개당 DTO 1개 + nested 클래스는 `V1beta1WorkspaceSsh.Password` 와 같은 방식이다.
- **예시 매니페스트**: `examples/crd.yaml` 의 두 문서를 클러스터 덤프에서 기계 생성하고 `spec.template`(PodTemplateSpec 전문 8천 줄)만 기존 축약본으로 교체. `operations` 는 구 계약 `ports[].external` 을, `workspaces` 는 `v1` 스키마를 들고 있었다.
- **테스트**: `WorkloadDtoDeserializationTest` 4건 — `expose.inference`(WS/OP 양쪽) · `suspendOption.commit` + `status.suspendCommit` · `tools[].type=vscode`.
- **문서**: `docs/aip-3585-workload-crd-sync/` 4종.

## 알려진 트레이드오프 / 하위 호환성

- **동작 변경 없음.** 추가한 필드를 읽는 코드가 0건이고 리컨실 분기도 그대로다. RBAC·웹훅 `rules` 도 리소스 plural 과 라벨 낙인 대상이 그대로라 변경 없다.
- 이전 빌드도 INFERENCE Workspace 때문에 죽지는 않았다 — Gson 이 모르는 필드를 무시하기 때문이다. 다만 그 필드를 **조용히 누락**했고, 이번 변경으로 모델이 계약과 같아진다.
- 예시 CRD 의 `spec.template` 은 여전히 축약본이다(containers/hostname/volumes). 이 파일을 실제 클러스터에 적용하면 pod spec 의 나머지 필드가 pruning 된다 — 예시 용도라는 기존 전제를 유지한다.
