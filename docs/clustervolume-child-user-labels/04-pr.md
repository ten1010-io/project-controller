# PR 문구

## Title
feat: ClusterVolume 자식 PVC/PV 에 부모 소유자 라벨 전파 (CREATE 웹훅 + transfer 대응 리컨실러)

## Summary
- ClusterVolume 컨트롤러가 만드는 복제/앵커 PVC·PV 에 부모 ClusterVolume 의 `aipub.ten1010.io/username`/`userid` 라벨을 전파한다. 자식이 `clustervolumes.aipub.ten1010.io/owner=<CV명>` 라벨로 부모를 가리키므로, userrelationship 웹훅의 비멤버 경로에서 이 라벨로 CV 를 조회해 라벨을 복사한다.
- PV 는 cluster-scoped 라 별도 웹훅 엔트리(`objectSelector: owner Exists`)로 CV 컨트롤러가 만든 PV 만 인터셉트한다 — CSI/시스템이 만드는 일반 PV 는 fail-closed 웹훅을 경유하지 않는다.
- PV 에는 AipubUser ownerReference 를 붙이지 않는다(붙이면 사용자 삭제 시 PV 가 GC 됨). 테스트로 고정.
- **transfer 대응**: `ClusterVolumeChildLabelReconciler` 가 "자식 username/userid = CV username/userid" 를 지속적으로 맞춘다(추가·교체·제거). CV 라벨 변경, 자식 생성/라벨 변경, 기동 시 CV onAdd(기존 자식 소급)가 트리거. CSI 가 만든 앵커 PV 도 CV 컨트롤러가 owner 라벨을 붙이는 순간 처리된다.

## Changes
- `LabelConstants`: `CLUSTER_VOLUME_OWNER_KEY` 추가
- `V1AdmissionReviewUtils`: `isPersistentVolumeRequest()`, `isPersistentVolumeClaimRequest()` 추가 (cluster-scoped 는 kind 로 판별)
- `UserLabelReviewHandler`: **admin 이 직접 만든 CV 에도 본인 라벨 주입**(#112 는 member 만 — CV 는 라벨이 유일한 소유자 기록이고 자식 전파의 원천이라 admin 생성도 찍어야 함. admin 에 AipubUser 가 없으면 라벨 없이 허용, Namespace 계약과 동일). PV CREATE `canHandle`. 비멤버 경로를 `resolveOwnerLabels()` 로 통합 — ① PVC/PV 에 CV owner 라벨(DNS label 형식)이 있으면 cluster-scoped GET → 라벨 복사, ② namespaced 는 기존 controller ownerReference 경로, ③ 없으면 무변경 허용. CV 404/라벨 없음 → 무변경 허용, 그 외 API 오류 → 500 (기존 owner 조회와 같은 계약). 멤버 직접 생성은 본인 라벨 우선(기존 유지)
- `mutating-webhook-user-v2.yaml`: `userrelationship-v2-clustervolume-pv` 웹훅 추가 — `persistentvolumes` CREATE `scope: Cluster`, `objectSelector` owner Exists
- 리컨실러: `V1alpha1ClusterVolume(+List)` DTO, `K8sApiProvider.clusterVolumeApi`, CV 인포머 + owner 라벨 셀렉터 PVC/PV 인포머(`SharedInformerFactoryProvider`, 이 팩토리의 PVC/PV 인포머는 CV 자식만 담음 — 주석 명시), `ClusterVolumeUtils`, `OnUpdateFilterFactory.labelsFilter/ownerLabelsFilter`, `RequestBuilderFactory.clusterVolumeChildToClusterVolume`, `ClusterVolumeChildLabel{Reconciler,ControllerFactory,Patcher}` + `CoreV1ClusterVolumeChildLabelPatcher`(merge patch), `ControllerConfiguration` 빈
- 테스트 33건 추가·1건 변경 (`UserLabelReviewHandlerTest` 13 추가 + admin CV 케이스 1건 동작 변경, `UserOwnerReviewHandlerTest` 1, `ClusterVolumeChildLabelReconcilerTest` 11, `ClusterVolumeChildLabelWatchTest` 8)

## RBAC 영향
- 라벨이 붙은 복제 PVC 는 `OwnershipPolicy` 대상 → 소유자 개인 Role 에 `resourceNames` 단위 update/patch/delete 가 생긴다(의도). 복제 PVC 삭제는 컨트롤러 자가치유로 재생성.
- 시스템 ns 의 앵커 PVC 는 namespaceSelector 제외/allowlist 라 라벨이 붙지 않고, 붙더라도 `AipubUserRoleReconciler` 가 Project 없는 ns 를 스킵해 Role 이 생기지 않는다.
- PV 는 OwnershipPolicy 대상 아님 → 권한 변화 없음.

## 알려진 한계
- allowlist 네임스페이스 안의 PVC 는 웹훅·리컨실러 모두 라벨을 붙이지 않는다(기존 정책).
- CV 컨트롤러가 자식 update 시 labels 전체를 덮어쓰는 구현이면 라벨 핑퐁 가능 — 개발 클러스터에서 확인 필요.
